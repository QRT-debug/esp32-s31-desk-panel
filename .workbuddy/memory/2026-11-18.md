## ★★★ 垂直对齐铁律（这次折腾了 5 轮才明白）

**LVGL 的 label 框 ≠ 字形框**。要让"数字墨迹底边"与某个 y 对齐：

```
label_y = target_y + base_line - line_height
```

本工程字体实测参数（`components/ui/src/fonts/ui_font_XX.c`）：

| 字体 | line_height | base_line |
|---|---|---|
| ui_font_14 | 14 | 4 |
| ui_font_20 | 20 | 4 |
| ui_font_24 | 24 | 5 |
| ui_font_28 | 28 | ? |
| ui_font_32 | 34 | ? |

例：点底 y=23、用 24px 字 ⇒ y = 23+5-24 = **4**。
**不要用 `lv_obj_align_to(..., LV_ALIGN_OUT_LEFT_BOTTOM)` 做这类对齐**——它按 label 框算，
会因 descender 天然偏高 4~5px；而且它的水平定位会顶到相邻对象的包围盒（弧虽只画顶部
90°，对象框仍是正方形）。

## 四角闪烁的最终结论

**不是状态栏造成的**：换成纯文字 WiFi 字形（`LV_SYMBOL_WIFI`）同样闪。
真正原因是**开机瞬态**——WiFi 连接 / SNTP / 首次数据 / LVGL 缓存预热期间
flash+PSRAM 访问量是稳态的数倍，与 RGB LCD DMA 抢 MSPI；负载降下来自行消失

## 22:23 修复：状态型按钮在页面重建后不同步

**现象**：播放中 → 回 HOME → 再进 AUDIO，按钮显示 `PLAY`（应为 `STOP`）。

**★ 插拔检测（两次踩坑才做对）**

第一次：`sd_card_ready()` 只是个静态标志，挂载后**永远返回 true** —— 拔卡图标不变。
⇒ **教训：凡"状态"不要用"操作成功时置位的标志"代表，必须有真实探测。**

第二次修：在 LVGL 定时器里 `sdmmc_get_status()` 检测拔出 + 每 30 秒尝试重挂。
- 拔出检测 ✅（秒级）
- 但插回要等 **30 秒**——因为重挂是阻塞操作（SD 枚举数百 ms），
  放在 LVGL timer 里会把界面卡住，只能拉长间隔换取流畅。

最终方案（`sd_card.c`）：
```c
bool sd_card_poll(void)        // 状态栏每秒调：只做「已挂载 → sdmmc_get_status」
                               // 失败 ⇒ 立即 esp_vfs_fat_sdcard_unmount + ready=false
static void sd_recovery_task() // 独立低优先级任务，1.5s 一次静默重挂
```
⇒ 拔卡 1 秒内变灰，插回 1.5~2 秒变绿，界面全程不卡。

**通用规律**：**阻塞操作（挂载/枚举/网络）绝不能放在 LVGL 的 timer 回调里**，
要么独立任务、要么拆成"轻量探测 + 后台动作"。

**API 坑**：IDF 6.x 的卸载函数是 `esp_vfs_fat_sdcard_unmount(base_path, card)`，
不是老版的 `esp_vfs_fat_sdmmc_unmount()`（后者已移除，只有 `_mount` 还在）。

## 11-19 晚 帧率探索：PCLK 30MHz 成功、切页动画失败

### 成功的部分
- **PCLK 25 → 30 MHz**（`components/BSP/CMakeLists.txt` 的 `LCD_PCLK_MHZ`），
  理论上限 48.5 → **58.2 fps**，真机**无闪烁、无色块、无撕裂** ✓
- **P2 刷新加快**（纯收益，无渲染负担）：
  - AUDIO 进度条 200ms → **100ms**
  - HOME 卡片 500ms → **250ms**
  - SYSTEM 数据 1s → **500ms**

### ★★★ 失败：切页滑入动画（已回退）
做法：每页放进 800x480 容器，切页时 x 从 +160 动画回 0（180ms ease-out）。
**结果：用户实测"比不加动画还卡"** ⇒ 已全部移除调用（`ui_slide_in`）。

**根因（重要工程结论）**：
- 位移 = 整屏重绘，每帧 768 KB
- 180ms ÷ 16ms = 12 帧 → PSRAM 需扛 **44.6 MB/s**
- PSRAM 带宽已接近极限 ⇒ 动画期间掉帧，主观比"瞬间切换"更差

### 最终结论（22:46 确认）
**根因 = esp_codec_dev 驱动版本**：旧版（我们原来的）`codec_mode` 是 ADC/DAC 单选枚举，
填 DAC 时 **ADC 数据通路层完全没初始化**（寄存器手动补也没用——驱动的 I2S 读取路由没接 ADC）。
厂商用的**新版 v2.x**（`adc_cfg`/`dac_cfg` 分开）才真正支持双工。
**换新版驱动 + 双句柄后，第一次读到非零麦克风数据（peak=72，样本有正负波动）。**

### 坑 1：esp_codec_dev 版本差异（最核心）
| | 旧版（我们原来的） | 新版（厂商用的） |
|---|---|---|
| cfg 结构 | `codec_mode` 枚举单选 | `adc_cfg` + `dac_cfg` + `pa_cfg` 分开 |
| 版权 | 2025 Apache-2.0 | 2025-2026 Modified-MIT |
| 目录 | `device/` + `include/` | 多 `src/` + `private_inc/` |
| API | `get_reg/set_reg`（3 参数） | `read_reg/write_reg`（5 参数：reg, reg_len, data, data_len）|
| i2c_cfg | 有 `.port` 字段 | **没有 `.port`**，只有 addr/bus_handle/clock_speed |
**→ 以后任何 codec 驱动，先确认版本！cfg 结构字段名都不一样。**

### 坑 2：组件管理器会还原 managed_components
`dependencies.lock` 里记录了每个组件的 **hash**，build 时**校验不符就重新下载旧版**，
手动复制的文件会被覆盖回去（表现为"改了又改不动"）。
⇒ 三种解法：①改 lock 的 hash ②删 lock 重新解析 ③**把组件本地化到 `components/` 目录
（最优——从此 build 完全离线，连网络等待都没了）**。我们用了 ③。

### 坑 3：`rm -rf` 被环境重定向回收站
`rm -rf managed_components/xxx` 实际**没删**（进了回收站）⇒ `cp -r` 时目标还在 ⇒
新文件复制不进去（或混入旧文件）。⇒ **删目录必须用 `[System.IO.Directory]::Delete()`**。

### 坑 4：引脚悬空检测的时机（假阳性）
`IO6 probe: FLOATING` 是**假阳性**——在 codec 初始化**之前**测，ASDOUT 本来就高阻。
⇒ **判断引脚是否悬空，必须在目标器件已经工作之后测**，否则测的是"器件未上电"。

### 坑 5：ES8389 关键寄存器（这个 codec 全记住了）
- `0x01` MISC：**TRI_BCLK/LRCK/ADCDAT 默认全 1（三态高阻）**，slave 模式必须清 0
- `0x64` ADC ANALOG ENABLE：**默认 0x30（ADC1/2 + PGA 全部 power down）**，0x8F = 全上电
- `0x26` ADC OSR VOLUME：默认 0xBF = 0dB（不是静音）
- `0x26` 0x00 = -95.5dB，FF = +32dB
- `0x03` CLOCK OFF 1：bit7 ADC_CLK_ON（默认 0 = 关！驱动会开）
- 驱动 `es8389_start → set_bias_on` 会写 0x64=0x8F、0x24=0x6A、0x25=0x0A
- ★ ES8389 手册已渲染：`Temp/es8389/`（40 页 PNG）；官方 PDF 在百度盘芯片资料目录

- **双句柄模式机**：`s_codec`(OUT 播放) / `s_rec_dev`(IN 录音)，`aud_enter(mode)` 互斥切换
  （互斥锁 s_aud_mux；先 close 在用 → 重配 I2S 时钟 → open 目标 → PA 切换）
- **默认开机进 REC（麦克风常开）**：电平表 / AI 对话随时可用；放歌切 PLAY，播完自动回 REC
- **双采样率**：播放 `AUD_RATE_PLAY=44100`，录音 `AUD_RATE_REC=16000`
  `i2s_set_rate()`：disable TX/RX → reconfig_std_clock → enable（~10ms，APLL）
- **PA 改应用层自管**（pa_cfg.pa_pin=-1，照厂商）：pa_set() 控 IO7；
  录音态强制关功放（底噪会经空气+电源灌进麦克风）
- `mic_level()`：分通道去直流（R 通道单端输入有 ~几十 counts 偏置）后取峰值，×4 显示

### ★★★ 44.1k ADC 垃圾数据之谜（本日最重要发现）
- 新驱动在 44.1k 下给 codec 配 **05=45 06=a4 07=d0 09=d1 = 48k 行**（分频表无 44.1k 行）
- 实测：**L 通道 min=-32768/max=32767 全幅垃圾**（16k 下干净 min=-70/max=27）
- 16k 时 BCLK=1.024MHz 有正确分频行 ⇒ 数据干净
- **⇒ ES8389 ADC 只能在驱动分频表支持的采样率下工作；44.1k 录音此路不通**
- 播放(DAC) 44.1k 用同一张表 —— 旧驱动时代手工 patch 表后 44.1k 播放是好过 ⇒ DAC@44.1k 预期正常

### ★★ 新版 esp_codec_dev 的 API 语义坑
**`esp_codec_dev_read()` 成功返回 0（ESP_CODEC_DEV_OK 状态码），不是旧版的"字节数"！**
我们曾把 0 当失败走了裸 I2S 兜底（数据其实一样，但 codec 层的错误日志被吞）。
⇒ 判据：`rd == ESP_CODEC_DEV_OK` 即成功，buf 已填满。

### 模式机的调用点

- `file_task`（flash 分区路径）：同上
- `diag_set()`：mode>=4 走 DAC → `aud_enter(PLAY)`；退出诊断 → 等任务退干净 → `aud_enter(REC)`
  0~3 档只在 PLAY 态有意义（s_play_open 才动 mute/PA）
- `audio_player_set_volume()`：未播放时只记 s_volume，起播时统一套用
- `audio_player_mic_level()`：`!s_rec_open`（放歌中）直接返回 0
