# 2026-11-20 · 麦克风全 0 三连根因 + 打通（旧驱动回归夜）

## 00:30~01:10 排查链

- **根因 1（APLL 互抢）**：init 按 44.1k+APLL 创建 I2S → APLL 占死 22.5792MHz → aud_enter(REC) 的 16k 请求 8.192M **静默失败**（i2s_common 只警告不报错）→ ES8389 时钟异常 → mic 全 0。修：init 直接按 16k+APLL 创建（开机即 REC 态，i2s_set_rate 短路），播放 44.1k 由 i2s_set_rate 换 DEFAULT 源。
- **根因 2（手动序列漏 bias_on 尾段）**：adc_manual_init 抄自"新驱动 open(IN)+补丁"，漏了 set_bias_on 的 0x69|=0x20、0x10=E4（写 E4 读回 C4=硬件自清 bit5，假差异）、0x64=0x8F；且全序列漏 0xF0=0x12（coeff 表每行标配）。
- **根因 3（时钟行 + 0x01）**：厂商例程 no_mclk=true 但 set_fs 按软件 dataformat 的 mclk=4.096M 查表 → **coeff ratio=256 行（05=41 06=04 07=C0 08=01 09=D1）实测能通**（PLL 系数与 BCLK 512k 差 8 倍也照录，厂商录音回放正常）；0x01 厂商固定 bit3=1（0x08），11-19 的"三态清除 0x00"补丁连 bit3 一起清了。
- **终态**：mic dbg `L dc=47 min=10 max=67 | R dc=43 min=22 max=81` —— 链路通（静场噪声底）。电平条取整后显示 0 属正常：显示值 = peak×400/32768，peak>82 才显示 ≥1，说话时应跳几十。
- 当晚 dump 快照 ≠ 打通态：dump 只有 27 个寄存器且含补丁覆盖值；逐条对照厂商源码 coeff_div 表 + set_fs + bias_on 才是完备态。
- I2S APLL 是单资源，两个频率互抢时第二方静默降级（只有警告行）。

## 01:12~01:25 播放时钟三轮终案

- **01:15 版（REC/PLAY 都 APLL 分时切换）失败**：IDF I2S reconfig **不释放已持有的 APLL** → 切播放请求 22.5792M 被拒 → `sample rate is too large` → enter PLAY failed，没声音。
- **终案**：REC 16k = DEFAULT 源（160M÷4.096M=39.0625，小数 1/16 可精确表示 → 零抖动）；PLAY 44.1k = APLL 独占（REC 态不碰 APLL → 永不互抢）。mic 链路在 DEFAULT 源下不受影响。
- **新坑（旧驱动 data_if 覆盖时钟）**：esp_codec_dev v1.x `audio_codec_data_i2s.c` 的 `set_drv_fs` 里 `if (clk_src)` 才覆盖 clk_cfg.clk_src；`audio_codec_i2s_cfg_t.clk_src` 不传（=0）时 open(OUT) 的 reconfig 把 i2s_set_rate 配好的 APLL **覆盖回 DEFAULT（jitter 91%）** → 纯音拖长。修：创建 data_if 时显式传 `.clk_src = (int)I2S_CLK_SRC_APLL`。
- **验证铁证**：`I2S_IF: STD: TX, sample_rate_hz: 44100, clk_src: 17`（17=APLL 枚举值）；"APLL occupied 22579193 vs 22579200" 是 APLL 硬件 0.3ppm 偏差的沿用提示，非冲突。双向切换（PLAY↔REC）各 2 次零报错。
- ESP32-S31 上 APLL 枚举值是 17（厂商例程日志的 clk_src:16 是另一型号/枚举，别照抄比对）。

## 02:18~02:26 白屏修复（复位→首帧期间全白）

- **根因**：厂商 BSP 在 lcd_init 尾部 `lcd_clear(WHITE)` + `LCD_BL(1)` 立即开背光，而 LVGL 首帧要等 audio init + WiFi（~4s）→ 白底空屏。
- **修复三件套**：① lcd_init 尾清**黑**且**两块 fb 都清**（LVGL 双缓冲交替扫描，只清一块闪）② backlight_init 只配 PWM duty=0 ③ lvgl_port flush_cb 首帧等过一次 vsync 后 `backlight_default()`（75%）点亮。日志时序：1262ms 配 PWM（不亮）→ 5552ms 首帧点亮。
- **验收**：复位后全程黑屏过渡，无白屏，用户接受黑屏等待时长。
- **残余**：bootloader 段（复位瞬间 ~0.3s，GPIO 未被固件接管）软件管不到；若背光 IC 默认态亮，下版 PCB 加背光脚下拉根治。
