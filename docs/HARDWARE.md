## 2. 显示屏（4.3" 800×480 RGB）

- 面板：WKS43WV067（HX8264/HX8664 时序，**无 GRAM** ⇒ 显存靠 PSRAM 双 framebuffer）

★★★ **显示时序是三条互相冲突的硬约束卡出来的唯一解，任何一项都不能单独改**（2026-11-22 定案）：

| 参数 | 值 | 卡的是什么 |
|---|---|---|
| PCLK | **40 MHz** | 必须 `160MHz ÷ (2×PCLK)` 为整数 ⇒ IDF 固定 `mo=2`，只有 **40 / 26.67 / 20 MHz** 是零抖动 |
| H_total × V_total | **1120 × 541** | ⇒ 帧率 = 40e6/605920 = **66.02 fps**。★ 帧率下限由**亮度**决定：CFF（临界闪烁频率）随亮度上升，背光 100% 时 **62Hz 会闪、64Hz 勉强、66Hz 有余量**。同时让有效区占 63.4%，给 DMA 留 36.6% 空闲 |
| `pclk_active_neg` | **true** | 40MHz 下建立/保持裕量被压缩，false 时**右侧 1~2px 白竖线**（行尾采错）；换成 true 才对上 |

**三条约束是怎么互相打架的（照着这张表就不会退错）：**

- **只降 PCLK 到 25MHz** ⇒ 帧率 48.5Hz < 60 ⇒ **矩形四个边缘 flicker**（VCOM 型：边缘像素无邻接、寄生电容与中心不同）。这就是最初"看着眼睛难受"的真因。10MHz(19.4fps) 表现为"更闪"⇒ 帧率越低越闪。

★★ **flicker 幅度由"上电时的偏压状态干不干净"决定，不是温度。**（11-22 修正，温度假设已被实测推翻）

| 上电方式 | 实测结果 | 原因（推断） |
|---|---|---|
| **隔夜断电后再上电**（约 10h，**未精确测量**；已知"断电几分钟仍然会闪"） | **完全不闪** | 液晶离子扩散回均匀分布 ⇒ 内部直流残留消退 ⇒ 电荷泵/VCOM 从零建立，状态干净 |
| 短时断电 / **烧录后热复位**（3.3V 不掉，面板从未复位） | **明显闪** | 残留电荷（秒级）+ **离子仍在原位（小时级）** ⇒ 偏压落在偏差大的工作点 |
| 已运行一段时间 | 闪逐渐减小 | 电荷泵/偏压自我收敛 + 离子重新分布 |

★ **两个时间尺度必须分开**（这是推翻"纯电容残留"的关键）：
- **秒~分钟级 = 电容**（3.3V 网络 MLCC + 电荷泵节点，漏电几十 µA 就够放净）
  ⇒ 解释"断电几秒不行"
- **小时级 = 液晶层内的杂质离子扩散**（≈ L²/D，L≈4µm，D 若在 1e-15 m²/s 量级 ⇒ 数小时）
  ⇒ 解释"断电几分钟仍不行、隔夜才干净"
★ **精确的消退时间没有测，也不建议去测**：每次上电都会重新积累直流残留（观察者效应），
  用"上电看一眼"的方式测，测的是被污染过的状态。**已知区间（几分钟 < t ≤ 隔夜）足够用。**

★ **推翻的假设**：曾以为是"温度特性"（冷机幅度大）——但断电 10 小时是**最冷**的情况，
实际却**最不闪**，与温度假设预测相反 ⇒ 否定。
★ 这也解释了历史上全部"随机"观测（"跑一阵就好""有时闪有时不闪""断电久就好"）：
**唯一的自变量是"面板这次上电复位得干不干净"**，与烧录动作、温度都无因果。
⇒ 判据：**烧录/热复位后那几分钟最容易看到；完整断电后开机最干净。**
⇒ 而 66Hz 的价值正在于：**即使偏压状态不干净（幅度大），频率也在 CFF 之上，所以看不见。**
- **只升到 32MHz** ⇒ `160/64 = 2.5` 小数分频，PCLK 周期在 25/37.5ns 间交替（±20%）⇒ 文字**波浪**。
- **只升到 40MHz 但用小 porch** ⇒ 有效区占 74.5%，DMA 连轴转，CPU 每次访问 PSRAM 都被仲裁延迟 ⇒ `render` 从 24ms 恶化到 **49ms**（19~41fps 抖动）。
- **把 porch 撑到 1120×576** ⇒ DMA 每帧有 40% 空闲，`render` 回到 24ms、46fps。**但 62Hz 在 100% 亮度下仍会闪**（CFF 随亮度抬升）。
- **V_total 收到 541（66Hz）** ⇒ 既不闪，DMA 仍留 36.6% 空闲，`render` 不变。
- **40MHz + 大 porch 但 `pclk_active_neg=false`** ⇒ 无波浪无闪，但**右侧白竖线**。
- **全部满足** ⇒ 无闪、无波浪、无竖线、无抖动。

⚠️ **40MHz 超商家验证值 60%**，属实测可用但余量很薄。若将来出现竖纹/边缘错位，第一嫌疑就是这里；退路是 **32MHz（不闪、有轻微波浪）**，不是 25MHz。
★ 商家原值 25MHz / HSW48 / HBP88 / HFP40 / VSW3 / VBP32 / VFP13 已归档，仅作对照。

**关于"会不会损坏屏幕寿命"（2026-11-22 结论）：不会，但要分清两件事 ——**

| 项 | 影响寿命？ | 理由 |
|---|---|---|
| PCLK 40MHz | ❌ 无关 | 它是**接口时钟**，只决定"数据传多快"，不改变液晶偏压、背光电流等任何物理工作点。超规格的真实代价是**采样余量变薄 → 可能出竖纹**，属**稳定性**问题，不是老化问题 |
| 66Hz 刷新率 | ❌ 可忽略 | 液晶极性反转是**电压驱动，不是机械磨损**，没有"翻转次数寿命"。手机 120Hz、显示器 144Hz 都是常态。行周期 39µs→28µs 只让像素充电时间略短（对比度略降），不影响寿命 |
| 背光 100% | ⚠️ 有，但属**额定工作** | 75%→100% 是"从 75% 平均负载回到 100% 额定负载"，**不是超载**。LED 寿命 = 规格书额定值（通常 2~3 万小时到 70% 亮度）。★ 反过来说：5kHz PWM 斩升压时峰值电流并不低，只是平均亮度低，所以 75% 并没有"保护"作用 |
| PSRAM 250MHz | ❌ 与屏无关 | 是芯片合封的 PSRAM，不经过面板 |

⇒ **真正需要留意的只有一件事：40MHz 的稳定性**（温度变化、批次差异可能导致竖纹回归），
建议正常使用观察一段时间；出竖纹就退 32MHz。**寿命方面不必焦虑。**

**定量依据（为什么寿命不必焦虑）：**

| 功耗项 | 量级 | 与 PCLK 的关系 |
|---|---|---|
| 背光 LED（4.3" 侧入式，100%） | **1.0 ~ 1.5 W** | 无关（由模组限流决定） |
| 面板逻辑 + 源/栅驱动 | 0.2 ~ 0.4 W | 刷新率 ↑36% ⇒ 小幅增加 |
| **RGB 接口输入级（PCLK 相关）** | **几十 mW** | +60%（动态功耗 ∝ f） |

⇒ PCLK 25→40MHz 带来的**增量 < 50 mW**，占面板总功耗 **< 3%** ⇒ 温升 < 1°C
⇒ 对寿命的影响**远小于"背光 75%→100%"这一项**，而那一项也属额定工作。

★ 想实测的话只有一条有意义的路：USB 电流计看整机稳态电流的变化量。
但普通电流计分辨率约 10 mA（= 50 mW @5V），**很可能看不出来 —— 看不见本身就是结论**：
变化小于 50 mW。

★ **诚实边界**：厂家只在 25MHz/60Hz 下验证过可靠性，40MHz 属**数据缺失**，
不等于"已知会坏"。风险排序：竖纹回归（显示异常）> 对比度略降 > 器件损坏（无过压/过流/过热，基本不会）。
★★ 另注：**"超频折寿"的真正机理是加压**（电场强度 → 电迁移/热载流子注入），
本方案**没有任何电压变化**（3.3V 未动，VGH/VGL/VCOM 由面板内部电荷泵自主产生），
所以不满足折寿的必要条件。

- 时序：HSW48 / **HBP160** / **HFP112** / VSW3 / **VBP32** / **VFP26**（总周期 1120×541）
- 行宽校验：`H_total × 2 = 2240`，`2240 ÷ 64（DMA burst）= 35` 整除。
  ★ 历史上"加大 porch 就失真"的真因是当时 H_total 变成 1008，`2016÷64 = 31.5` 不整除、突发跨行错位 —— **不是 porch 本身不能加**。
- **引脚（全部 IOMUX 直连）**：

| 信号 | GPIO | 信号 | GPIO |
|---|---|---|---|
| HSYNC | 44 | DE | 43 |
| VSYNC | 45 | PCLK | 40 |
| B3~B7 | 8,9,10,11,12 | G2~G7 | 13,14,15,16,17,18 |
| R3~R7 | 19,33,34,36,35 | — | — |

## 4. 音频（详见 BOARD_AUDIO.md）

| 器件 | 位号/型号 | 说明 |
|---|---|---|
| Codec | **U3 ES8389** | 2×ADC + 2×DAC，I2C 7 位地址 **0x10**（8 位写 0x20） |
| 功放 | **U4/U5 NS4150B** ×2 | D 类，BTL 输出到 SPKL/SPKR 两个 2P 座 |
| 麦克风 | MIC1/MIC2（模拟 MEMS） | MIC1 接 codec 的 MIC2 通道（左右交叉） |
| I2S（ESP32 侧） | BCLK=**IO3**、WS=**IO4**、DOUT=**IO5**、DIN=IO6 | MCLK=IO2，但 **R56 标 NC 未贴** |
| 功放使能 | **IO7**（高有效，R11 10k 下拉） | 复位后默认静音 |

**已知事实**：`DSDIN`/`ASDOUT` 是 codec 侧命名 ⇒ ESP32 的 `dout` 接 IO5、`din` 接 IO6，接反就"只能放音不能录音"。

## 5. 三个 USB 口（别混）

| 丝印 | 类型 | 数据线 | 用途 |
|---|---|---|---|
| **COM** | Type-C 16P | `USB_D±` → **CH343P** → UART0；DTR/RTS 自动下载 | **烧录 + 看日志（COM5）** |
| **USB** | USB-A 母座 | `USB_DM/DP` → 模组 pin41/40（原生 USB） | OTG **Host**（读 U 盘/键鼠），VCC 直连 SYS_5V **对外供电** |
| **PWR** | Type-C 16P | D± 串 R50/R51 标 **NC** | **纯供电，不能传数据** |

电源：两个 Type-C 的 VBUS 并联 → `F1`（1.5A 自恢复保险）→ `SYS_5V` → `U10 SY8089A1AAC` 降压 → 3.3V。

## 6. TF 卡座（SDMMC 4-bit）

> ★★ **2026-11-18 更正**：早期本文写"SD_CLK=31 / CMD=32 / D0~D3=27~30"是**错的**——
> 那是把原理图文本里的"模组引脚号"误当成了 GPIO 号。用 300 DPI 重渲染原理图核对后，
> 实际连接如下（6 条线各经 22Ω 串阻 R63~R68）：

| 信号 | GPIO | 模组引脚 | 串阻 |
|---|---|---|---|
| SD_D0 | **IO20** | pin 26 | R63 22R |
| SD_D1 | **IO21** | pin 27 | R64 22R |
| SD_D2 | **IO22** | pin 28 | R65 22R |
| SD_D3 | **IO23** | pin 29 | R66 22R |
| SD_CLK | **IO24** | pin 30 | R67 22R |
| SD_CMD | **IO25** | pin 31 | R68 22R |

- 与屏、音频、I2C **零冲突**；
- **SDMMC 是独立控制器 + 独立 DMA，不占 MSPI** ⇒ 读卡不会像 flash 那样打断 LCD DMA（这是它能当播放源的关键）。

## 8. 总线共用关系（理解一切"闪烁/卡顿"的钥匙）

```
        ┌──────────── MSPI 总线（共享）────────────┐
CPU ────┤  Flash 16MB        PSRAM 16MB           │
        └────────┬───────────────────┬────────────┘
                 │                   │
           代码/文件读取        RGB LCD DMA 持续读 50MB/s
                                   ↑
                          CPU 读 flash / 写 PSRAM 会打断它
                          ⇒ 屏幕条纹（已用"音频预载 PSRAM"解决）
```

- SD 卡走 **SDMMC 控制器**（不在上图里）⇒ 未来用它放歌不会引起条纹；
- I2S 音频 DMA 走内部 RAM，不占 MSPI。
