## 继承的关键约束（改代码前必看）

1. **写 flash 会撕裂画面**：`nvs_commit` 期间禁 i-cache，LVGL 代码在 flash 里 ⇒ stall ⇒
   flush 等 vsync 200ms 超时。所有写 NVS 都在"画面静止"时做；配网保存前先 `backlight_set(0)`。
2. **`strlcpy` 不是 `snprintf`/`strncpy`**：目标缓冲小于源时后两者会触发
   `-Werror=format-truncation` / `stringop-truncation`（本会话踩了 4 次）。
3. **新增 .c 必须 `idf.py reconfigure`**，否则链接期报 `undefined reference`（长得像函数没写）。
4. **中文必须用 `ui_font_cn18*`**，`ui_font_14/20/32` 是 Montserrat 系，不含汉字会渲染成方块。
5. **LVGL 场景对象坐标是相对"内容区"**（已扣 padding），算尺寸时要用 `宽-2*pad`。
6. **PSRAM 被硬件写过后要 `esp_cache_msync(INVALIDATE)`**，否则 CPU 读到脏数据（壁纸会花）。


## 板子三个 Type-C 的分工（新会话最容易搞错）

| 口 | 芯片 | 用途 |
|---|---|---|
| PWR | 无（D± 标 NC） | **纯供电，不能传数据** |
| COM | **CH343P** | **烧录 + 看日志（COM5）**，带 DTR/RTS 自动下载 |
| USB-A 母座 | 原生 USB | OTG **Host**（读 U 盘），**不能接电脑烧录**——VBUS 直连 SYS_5V，接电脑会倒灌 |

★ 只插 PWR 时设备能跑、WiFi 能连，但**没有 COM5**，烧录不了。
★ 原生 USB 口要烧录必须进下载模式 + 断 VBUS 的线，不值得（每次要按 BOOT）。

## 壁纸规格（换图时按这个来）

- **必须 JPEG**：S31 硬件解码器只认 JPEG，PNG/WebP 读不出来
- **必须 800×480**：`scene_clock.c` 里校验 `info.width==800 && info.height==480`，
  不匹配直接跳过（不缩放，避免软解慢+糊）
- **横屏 5:3 最佳**：其他比例要裁切，竖屏会损失 60% 主体
- **避免大面积纯色**：烧屏风险最高（已排除一张纯粉色图）

## 掉电（POWERON 复位）的原因

上传壁纸时出现过一次 `rst:0x1 (POWERON)`：**SD 写入 + WiFi + 背光 75% 同时发生，
电流峰值把供电电压拉下来**。不是软件崩溃。
⇒ 换 5V/2A 充电器直插；软件可选缓解：上传时把背光压到 20%。

## 烧屏这件事（做屏保必须考虑）

这块屏 VCOM 出厂未校准，**大面积固定图案比纯黑更伤屏**。
屏保本来是为了护屏，如果加壁纸反而可能出现残影 ⇒ 必须配：
轮换（每次随机）+ 每 4 小时偏移 ±4px + 遮罩降对比。


## ★★★ 屏幕这条命：改动前必读 docs/HARDWARE.md 第 20~110 行

**现役参数（11-22 定案，四症状全清）：**

```
PCLK 40MHz · H_total 1120 × V_total 541 · 66.02 fps
pclk_active_neg = true
porch: HSW 48 / HBP 160 / HFP 112 · VSW 3 / VBP 32 / VFP 26
背光 75%（可配，10~100）
```

**四条红线，每条都是实测踩出来的，改任意一条立刻复发：**

| 改动 | 症状 | 原因 |
|---|---|---|
| PCLK 降到 25MHz | **矩形边缘 flicker** | 48.5Hz < CFF（临界闪烁频率），帧率低于人眼融合阈值 |
| PCLK 用 32MHz | **文字波浪** | `160/64=2.5` 小数分频，周期在 25/37.5ns 间交替 |
| PCLK 用 80MHz | 面板采不住 | 建立窗口只剩 7.5ns，规格要 30ns |
| `pclk_active_neg=false` | **右侧 1~2px 白竖线** | 行尾采样点落在建立窗口外 |
| 40MHz + 小 porch | `render` 从 24ms 恶化到 49ms | DMA 连轴转（74.5% 占用），CPU 访问 PSRAM 被仲裁阻塞 |

★ **零抖动的硬约束**：`160MHz ÷ (2×PCLK)` 必须整数（IDF 固定 `mo=2`）⇒ 只有
**40 / 26.67 / 20 MHz** 可用。这三个里 66Hz 只有 40MHz 做得到。

★ **历史误判澄清**：以前说"加大 porch 就失真"——**真因不是 porch**，是当时 `H_total=1008`，
`2016÷64=31.5` 不整除导致 DMA 突发跨行错位。现在 1120 是整除的，porch 该加就加。

★ **别再用"降 PCLK 治波浪"**：那条来自 25MHz 之前，已被 40MHz 全清推翻。

## flicker / 残影的物理结论（别再重复排查）

- 根因是**面板 VCOM 出厂未校准** + USB 5V 共地直流回路，**软件改不了 VCOM**。
- **断电隔夜能洗掉**（离子扩散，小时级）；短时断电/热复位不行（电容是秒级、离子还在原位）。
- RGB 接口无命令通道 ⇒ **读不到也写不了 VCOM**。
- 休眠（关背光+清黑）保护背光和防烧屏，**但不能替代断电**。
- 判据：**面板这次上电复位得干不干净**，与烧录动作、温度都无关。
