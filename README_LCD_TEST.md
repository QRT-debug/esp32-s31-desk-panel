# 屏幕测试工程（WKS43WV067-WCT / 800×480 RGB）

目标板：慧勤智远 ESP32-S31 CB V1.1 + 4.3" 800×480 RGB 触摸屏
驱动 IC：`HX8264-D03`（源极）+ `HX8664-B`（栅极），**无 GRAM**

---

## 一、怎么编译烧录

VS Code 里正常 Build / Flash 即可（环境用的是 `D:\esp\.espressif\v6.1\esp-idf`，target `esp32s31`）。

命令行方式（PowerShell）：

```powershell
cd C:\Users\Admin\Desktop\sample_project
. .\idf_env.ps1
idf build
idf -p COM5 flash monitor
```

`COM5` 是 `.vscode/settings.json` 里记的串口，按实际情况改。

**烧录波特率用 921600**（236 KB 约 4.2 秒烧完）。默认的 460800 也能用，115200 最保险但慢 5 倍。

★ **烧录过程中绝对不要按板上的 RESET 键** —— 会切断 USB 串口，esptool 报
`No more data to read from the serial port`，固件写到一半就废了，必须整片重烧。

`idf_env.ps1` 里已经封装好：直接敲 `flash` 就是 `-p COM5 -b 921600`。

## 二、8 个画面各测什么

程序每 4 秒自动切换一个画面，左上角有 `n/8 名称` 标签。
**串口输 `1`~`8` 跳到指定画面并停住，输 `0` 恢复自动轮播。**

| # | 画面 | 正常应该看到 | 异常说明什么 |
|---|---|---|---|
| 1 | **纯色**（白/黑/红/绿/蓝/青/品红/黄，每个 0.6 s） | 颜色满屏、均匀、无杂点 | 有**横向白条/亮线** → 信号完整性问题（这块 V1.1 板 RGB 线上一颗串阻都没有，见下）；颜色偏 → 伽马或背光 |
| 2 | **灰阶 16 级** | 16 个平滑台阶，相邻可分辨 | 中间几级"并在一起" → 位深/伽马；出现明显色带 → RGB565 正常现象（绿 6bit、红蓝 5bit） |
| 3 | **R / G / B 三原色渐变** | 三条各自从黑渐变到纯色 | 某条不发色 → 该通道数据线虚焊；红绿互换 → 位序错 |
| 4 | **棋盘格 8/4/2/1 px** | 四块从粗到细，1px 块仍能分出黑白 | 1px 块糊成灰 → 带宽/串扰；出现彩色摩尔纹 → 采样相位 |
| 5 | **1px 黑白竖条纹** | 近看细密竖线，远看均匀灰 | 出现彩色条纹或粗细不均 → **相邻像素串扰**，这条最严苛 |
| 6 | **对齐** | 1px 白框四面完整；四角 L 标（左上红/右上绿/左下蓝/右下黄）；中心十字居中；两条对角斜线连续 | 边框缺一边 → 行列偏移；斜线断裂 → 时序参数错 |
| 7 | **移动竖条 60 帧** | 白条从左扫到右，**能看到拖尾**（本屏响应 30~40 ms，必然有） | 拖尾超过 2 个条宽 → 响应差（屏本身）；上下错位 → 双缓冲没同步 |
| 8 | **信息页** | 显示分辨率、PCLK、理论/实测帧率、PSRAM、帧缓冲地址 | 实测帧率远低于理论 → tick 或 vsync 有问题 |

## 三、先看第 8 页的两个数

```
PCLK   25 MHz
FPS    theory 48.5  measured ??
```

- **理论值**：`25 MHz ÷ (976 × 528) = 48.5 fps`
  （976 = 800 + HSW 48 + HBP 88 + HFP 40；528 = 480 + VSW 3 + VBP 32 + VFP 13）
- **实测值**：启动时连续刷 30 帧测出来的

**如果实测明显低于理论（比如 33）**，说明 `CONFIG_FREERTOS_HZ` 被改回了 100。
本工程已设为 **1000**——因为等 vsync 用的是 `vTaskDelay(1)`，100 Hz 下就是 10 ms，
而一帧只有 20.6 ms，白等 10 ms 会让帧率掉三分之一。

## 四、改 PCLK 探"白条边界"

像素时钟是**编译期**常量，改法：

```powershell
idf -DLCD_PCLK_MHZ=30 build      # 或 33
```

或者直接改 `components/BSP/CMakeLists.txt` 里的默认值。

| PCLK | 理论帧率 | 说明 |
|---|---|---|
| **25 MHz** | 48.5 fps | **商家验证值**，先跑这个 |
| 30 MHz | 58.2 fps | 超规格，可能出白条 |
| 33 MHz | 64.0 fps | 超规格更多 |

**判据**：如果 25 MHz 就有白条，那是**板子的问题**（不是代码），
直接对应商家 V1.2 要补的那 14 个 RC；
如果 25 MHz 干净、30 MHz 才出，那就是屏/走线的余量边界，记录数值即可。

## 五、已知前提（别当成 bug）

1. **本屏无 GRAM**——每一帧都靠 RGB 接口实时扫描，所以**任何时序/边沿问题都会直接显示成白条或错位**，不会像 SPI 屏那样"错一帧下次覆盖"。
2. **V1.1 的 RGB 16 根数据线 + 4 根控制线上没有任何串联电阻**（原理图第 2 页可查）。这是 V1.2 才补的，属于已知短板。
3. **帧缓冲在 PSRAM，双缓冲**（`fb[0]` / `fb[1]` 各 768 KB）。
   所有画面都是整帧重绘再提交，不做局部刷新——因为局部刷在新的 fb 上不会保留。
4. **背光是 GPIO38**，`lcd_init()` 里已经做了"先关背光 → 初始化 → 清白屏 → 开背光"的顺序，避免上电花屏。
5. 屏的 `LCD_RST`（40 脚）在规格书里是 **NC**，复位靠 5V 上电自动完成，代码里没有复位脚。
